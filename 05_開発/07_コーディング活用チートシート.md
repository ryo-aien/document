# GPT-5 コーディング活用チートシート

GPT-5 を使う際のプロンプト設計は、従来のモデルとは少し異なります。API やコーディングツールで最大限活用するためのポイントをまとめました。

---

### 1. 正確に書き、矛盾を避ける

GPT-5 は従来より指示に従う性能が大幅に向上しましたが、その副作用として **曖昧または矛盾する指示**（特に `.cursor/rules` や `AGENTS.md` 内の記述）は処理が難しくなる場合があります。

---

### 2. 適切な推論レベルを選ぶ

GPT-5 は常にある程度の推論を行います。

* **複雑なタスク** → 高い推論レベルを使用する
* **単純なタスク** → 「中」または「低」の推論レベルを選ぶと過剰思考を防げます。

---

### 3. XML風の構文で指示を整理する

Cursor との利用では、**XMLライクな構文**で文脈を与えると効果的です。

例:

```xml
<code_editing_rules>
  <guiding_principles>
    - すべてのコンポーネントはモジュール化し再利用可能にする
    - ...
  </guiding_principles>

  <frontend_stack_defaults>
    - スタイリング: TailwindCSS
  </frontend_stack_defaults>
</code_editing_rules>
```

---

### 4. 強すぎる言葉を避ける

他のモデルでは以下のような強調表現を使っていたかもしれません：

* **「必ず徹底的に調査せよ」**
* **「完全な情報を揃えてから回答せよ」**

しかし GPT-5 に対しては逆効果になりやすく、**必要以上にツール呼び出しや調査をやりすぎる**ことがあります。

---

### 5. 計画と自己反省の余地を与える

ゼロからアプリを作るときには、**自己反省ステップを挟むよう指示**すると成果が向上します。

例:

```xml
<self_reflection>
  - まず採点基準（ルーブリック）を考える
  - 5〜7カテゴリで世界水準のアプリに必要な要素を定義
  - この基準を使って内部で反省と反復を行う
  - もし基準を満たさなければ最初からやり直す
</self_reflection>
```

---

### 6. エージェントの「熱心さ」を制御する

GPT-5 はデフォルトで文脈収集に熱心ですが、**プロンプトで制御可能**です。

* ツール使用の上限（予算）を設定
* 「いつ徹底的に調査するか」「いつ軽めに済ませるか」を指定
* 必要に応じてユーザー確認の有無を制御

例:

```xml
<persistence>
  - 人間に確認を求めない
  - 最も合理的な仮定を選び、それを記録して処理を進める
</persistence>
```
